# 随心模式脑图翻卡改造：独立交接包

整理日期：2026-11-27。

## 给接收资料的 AI

你无法访问原项目。请只根据这个文件夹评估 Memory Anki「随心模式中的思维导图翻卡界面」如何升级，不要假定自己已经读过原项目或看过实际运行页面。

阅读顺序：

1. `01-产品与交互现状.md`：对象、页面结构、实际交互、默认设置、边界状态。
2. `02-升级评估任务书.md`：本次目标、允许改变的范围、期待交付和验证方法。
3. `03-截图索引与待补证据.md`：截图采集状态、需要观察的实际场景。
4. `04-技术依据与实现约束.md`：技术栈、源码证据、性能和状态连续性要求。

## 资料可信度

- 本包来自当前项目源码和项目内交互文档的静态核对。
- 代码能证明存在相应逻辑，但不能单独证明运行时视觉和手感已经达到目标。
- 原交互文档有部分默认值及细节落后于代码，本包已指出明确发现的差异。
- 本包不是已完成的设计方案，更不是确认存在缺陷的测试报告。
- 截图是否已经取得，以 `03-截图索引与待补证据.md` 为准。没有图片文件的条目不是已经采集的截图。
- 不得把示意布局、源码推断或文档愿景冒充实际截图和实测事实。

## 用户最重要的诉求

全面评估视觉、前端手感和交互，但要做得更深入，而不是增加更多功能、按钮和说明。

文案与信息设计原则：避免不必要的二级标签和描述，让布局做解释，按钮文字能自己说清的不加说明。

当前阶段只评估和设计，不要求直接修改项目。若提出改变学习逻辑、评分规则、状态机或数据结构，必须与纯视觉改造明确区分。

## 一个必须先理解的区别

这是「脑图节点逐层揭示 + 复习单元整屏切换」的双层交互，不是普通正反面闪卡。不要只设计一张正面、一张背面和一个翻转动画。

请先说明资料足以支持哪些判断、还缺什么原始证据；对没有截图、录屏或实测支撑的判断标记为假设。随后再给诊断、推荐方向、具体设计与验收方案。
