## 技术栈

前端 React 19.2、TypeScript 5.9、Vite 8、Tailwind 4；脑图使用 @xyflow/react 12 的 React Flow、自定义节点和树布局。界面基础含 Radix UI、lucide-react，具有 React Query 等依赖。已有 Vitest、Testing Library、Playwright。

本次不是要求替换整个画布技术栈。单纯换脑图库可能牵连编辑、内容持久化、视野恢复、揭示投影、节点徽标和题目关联。

## 底层揭示与输入

`modules/memory/domain/review-entity/model/review-flow-tree.ts` 定义三态和按层/逐张推进、批量范围、收卡、可见树投影。

`useRevealSession.ts` 有动画帧队列和不同推进策略。随心面板显式使用 `pendingAdvancePolicy: latest-only`。视觉升级不能增加输入排队造成的长时间追赶，也不能让旧动画把新状态覆盖掉。

`FlipCardMindMapPanel` 在随心中使用 compact 密度，因此共用组件中另一套手机“上级/下一个/揭示/全局”导航栏在这一场景不会展示。不要因为源码中存在这组按钮就把它画进随心现状。

编辑/复习切换采用软同步、保留视野，避免重建 React Flow。随心复习点击节点的视野策略为 preserve；键盘揭示另有 follow 请求。

## 节点内容与可读性

底层节点卡片基础字号约根 16px、一级 14.5px、深层 13.5px，行高约 25/22/21px；实际阅读效果受缩放、字体和显示设备影响。

长文本支持折行和真实测量。布局使用约 18 个全角字符的舒适宽度策略，长内容可拓宽，存在硬上限。不要固定所有节点等宽等高而不验证长内容。

标题富文本与正文渲染是不同路径。正文支持受限 JSON 富文档中的图片、公式、表格、列表等，并非任意 HTML。图片有加载与尺寸变化问题，需要实测。

通用节点遮盖与复习树的“待回忆”投影不能简单等同；不能先验保证揭示前后卡片尺寸完全不变。

证据定位：shared/ui/mindmap-canvas/nodeCardModel.ts、layout.ts、useNodeCardMeasure.ts、NodeCardChrome.tsx；shared/ui/rich-document/RichDocument.tsx。

## 镜头参数

```text
默认缩放：1
手动缩放：0.12–1.4
普通 fit 最大：1.35
手机 fit：0.18–1.15
手机编辑 fit 最低：0.85
揭示入镜边距：32px
揭示入镜平移：200ms
```

默认精确为 1 的源码注释指出 Windows 上 0.99 一类非整数缩放可能让字形发虚。设计不能只按缩略图判断文字质量。

范围、单元或模式变化时需保护用户空间定位；视野中心对应节点被删除时有 fallback，不能一律 fit 整树。

## 手势与性能

底层有 React Flow 手势、长按菜单、轴向平移分流和文本/编辑输入避让。分流只在适用配置下生效，实机仍需验证。

源码静态研究发现的阈值：约 48 节点起可视区域渲染、120 节点起简化装饰；大批次超过 8 张翻转或 12 张发牌时跳过相应批次动画。它们是现有策略，不代表已测得所有设备都流畅。

快速输入会取消旧翻转动效；prefers-reduced-motion 下跳过相关动画。不可让播放完成成为下一次操作的前置条件。

避免大面积实时 backdrop-filter、复杂滤镜以及每个节点永久循环动效。评分坞已有不透明背景的性能取舍。

## 需额外验证的实现风险

静态研究注意到直接显示与两阶段模式在某些反馈事件判定路径并不完全一致。外部方案不得假定两者音效/动画一定相同。应通过实际操作与事件路径核对后决定是否修复。

任何“现在卡顿”“手机误触严重”“字号太小”等判断均需原始画面和设备实测，本包不将它们写作已确认缺陷。
