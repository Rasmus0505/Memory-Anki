## 四、PDF 识别顺序

### 1. 先做目录，不先写题

先建立完整目录表：

| PDF 页码 | 书页 | 章节 | 分节 | 题目/解析内容 | 备注 |
|---|---|---|---|---|---|

题目 PDF 和解析 PDF 必须分别记录页码。不能把书页当成 PDF 页码。

### 2. 再逐页识别

每道题至少记录：

- 题号；
- 来源标签；
- 老师；
- 版本和年份；
- 学科；
- 章节和分节；
- 题干；
- 全部选项；
- 答案；
- 解析；
- 核心考点；
- 题目 PDF 页码；
- 解析 PDF 页码；
- 对应宫殿 ID；
- 对应节点名称；
- 对应节点 UID；
- 识别置信度；
- 待核对内容。

来源标签示例：

- 【冬青老师｜333选择题｜2027版】
- 【凯程老师｜333真题｜2026版】
- 【凯程老师｜311真题】
- 【丹丹老师｜自命题】

只有原 PDF、已有记录或题目本身明确显示的信息才能填写老师、来源和年份。

### 3. 视觉不清晰时

按以下顺序判断：

1. 同页上下文；
2. 题目选项；
3. 对应解析页；
4. 已有同题或同源题；
5. 学科知识；
6. 仍不能确认就写“待核对”。

禁止为了完整而编造文字或答案。

## 五、题目去重与来源合并

使用以下标准建立题目身份：

题干 + 选项 + 答案 + 核心考点。

- 四项完全相同：不新增题目，只在来源元数据中增加来源。
- 题目内容相同但年份不同：保留多个年份来源。
- 题目内容相同但老师/版本不同：保留多个老师或版本来源。
- 题干相近但选项、答案或考点不同：不要自动合并，分别保留。
- 已删除题目不能重新绑定，除非用户明确要求恢复。
- 没有合适节点的题目放入“待归类题目”，同时提出建议节点名称。

## 六、识别记录规则

在每个原 PDF 同目录创建或增量更新：

原PDF文件名_AI识别记录.md

写入前先检查文件是否存在：

- 不存在：新建；
- 已存在：完整读取，只追加新页码、新题目和本次变更记录；
- 禁止覆盖旧识别结果；
- 旧记录中的不确定项不能被静默删除，只有有新证据时才能修订，并记录修订理由。

识别记录必须包含：

1. PDF 基本信息；
2. PDF 文件完整性检查结果；
3. 完整目录、章节、分节和页码范围；
4. 已识别页码；
5. 每道题的来源、题干、选项、答案、解析、考点、节点和页码；
6. 识别置信度；
7. 待核对内容；
8. 待归类题目；
9. 新增、重复、修订、来源补充和绑定统计；
10. 数据库备份路径；
11. 数据库写入批次；
12. 写入后的验证结果。

## 七、数据库写入安全流程

### 写入前

1. 创建带时间戳的数据库备份。
2. 生成按宫殿拆分的写入计划。
3. 每个计划必须明确列出本次章节的活动题目 ID。
4. 校验每个题目属于目标宫殿且未删除。
5. 校验每个 node_uid 存在于目标宫殿的 editor_doc。
6. 校验每个题目的宫殿 ID、节点 UID 和绑定理由。
7. 校验没有题目同时出现在 bindings 和 unbound。

### plan.json 格式

{
  "palace_id": 39,
  "question_ids": [469, 470],
  "run_id": "pdf-reconcile-YYYYMMDD",
  "source": "manual",
  "bindings": [
    {
      "question_id": 469,
      "node_uids": ["节点UID"],
      "confidence": 0.96,
      "reason": "题目答案和解析共同指向该节点"
    }
  ],
  "unbound": []
}

question_ids 是安全边界，不能省略。它只能包含本次章节实际处理的活动题。没有合适节点的题目必须列入 unbound，并在识别记录中写明建议新节点。

### 写入规则

1. 使用项目的安全绑定工具，并传入明确的 question_ids。
2. 不要使用 replace_scope=palace，除非用户明确要求重建整座宫殿。
3. 多个宫殿共用一个数据库时，不能并行写入同一数据库。
4. 写入必须在一个事务中完成。
5. 任一校验或写入失败，必须 rollback。
6. 不能删除其他老师、其他章节或其他宫殿的绑定。
7. 写入后检查每个题目绑定数、节点存在性和来源元数据。

- 识别记录存在且逐题条目数量正确；
- 数据库备份存在。
