# 复习排期设计（当前实现）

> 这份文档描述**代码现在真正在做什么**，不是旧方案或计划。改排期规则时同步改这里。
> 对应实现：`apps/api/src/memory_anki/modules/memory/application/`
> （`unit_scheduler.py`、`unit_fsrs_adapter.py`、`unit_intraday.py`）。
>
> 最后更新：2026-10-25（新卡固定 30 分钟 → 第2天 → 第3天 → 第5天，之后交给 FSRS）。

## 一、一句话总览

- **调度单位是「复习单元」**：脑图上的一个永久标记（L1/L2…）及其下游内容。不是单个节点。
- **新卡前期固定四轮**：当天 **30 分钟**复查一次 → **第2天** → **第3天** → **第5天**；
  第 5 天那次复习之后交给 FSRS。
- **当天间隔**：分钟级重练由产品自己控制（重练通过后 30 分钟再复查；
  忘记/困难 10 分钟 → 1 小时 → 3 小时）。
- **学习日 03:00 翻页**：凌晨 0:00–3:00 仍算前一天。

## 二、天级间隔（完整表）

| 你的评分 | 单元当前状态 | 下一次什么时候出现 |
|---|---|---|
| 记得 / 轻松 | 第一次学（从未通过） | 当天先 **30 分钟**复查一次，复查通过 → **第2天（明天）** |
| 记得 | 已完成第 1 轮固定复习（排到第2天） | **第3天**（再隔 1 天） |
| 记得 | 已完成第 2 轮固定复习（排到第3天） | **第5天**（再隔 2 天） |
| 记得 | 已完成第 3 轮固定复习（排到第5天） | **交给 FSRS**，但前 30 天每次最多翻倍 |
| 轻松 | 还在四轮固定期内 | 直接取最后一档：**再隔 2 天**，之后交给 FSRS |
| 记得 / 轻松 | 成熟单元（间隔 ≥30 天） | 交给 FSRS，不再设上限 |
| 忘记 | 任何状态 | **今天**再练（10 分钟 → 1 小时 → 3 小时），并从第一轮固定复习重来 |
| 困难 | 任何状态 | **今天**再练（同上），固定期内退一档；成熟单元保持 FSRS 路线 |
| 忘记 / 困难 → 当天重练时通过 | 任何状态 | 先 **30 分钟**再复查一次；复查通过才排天级间隔 |
| 任何通过 | 还没到期（提前复习） | **不改排期**，只记录这次复习 |

补充规则：

- **通过至少排到次日**：任何“通过”都不会留在今天（30 分钟复查期间除外）。
- **固定期靠计数器，不靠“上一次间隔”**：四轮固定复习的间隔是 1、1、2 天，前两档重复，
  所以单元上持久化一个 `early_step`（已完成的天级固定复习数，0–3）。旧数据没有这个值时会先按
  已排间隔推断一次（1 天→0、2 天→1、3 天→2、更远→已完成），之后每次评分都写回。
- **前期固定只认“实际排到的间隔”**，不认 FSRS 的内部稳定度。原因：`困难` 在 FSRS 里是
  “回忆成功但吃力”，会把稳定度抬高好几倍；如果拿它当间隔依据，就会出现“点了困难反而被排到
  3 天后”。
- **前期之后有增长上限**：间隔不到 30 天时，下一次最多是上一次的 **2 倍**（最少 3 天）。
  FSRS 想排得更短时照它的；到了 30 天以上才完全交给 FSRS。
- **FSRS 参数**：目标保持率 `0.9`、最长 `365` 天、自身 fuzz 关闭；≥7 天的间隔加一个按单元 ID
  计算的 ±5% 抖动，避免同一天学的单元永远同一天到期。
- **考试冲刺**：只把超出考期的日期**拉近**，绝不延长；失败仍然当天重练。
- **显示档位 `stage_index`**（0/1/3/7/14/30/60/120/240/365）只是兼容投影，不参与排期；
  面板按真实间隔分组。

## 三、分钟 / 小时级间隔（同一天内）

| 场景 | 间隔 | 说明 |
|---|---|---|
| 第一次通过后的复查 | **30 分钟** | 只复查一次；通过后进入第2天 |
| 重练通过后的复查 | **30 分钟** | 重练（忘记/困难后再次出现）评「记得」也要再复查一次 |
| 忘记 / 困难 第 1 次重练 | **10 分钟** | |
| 第 2 次重练 | **1 小时** | |
| 第 3 次重练 | **3 小时** | 当天最后一次 |
| 一天最多重练 | **3 次** | 之后排明天，不在当天反复出现 |
| 学习日结束前 | **15 分钟**内放不下 | 直接排明天（学习日 03:00 结束） |
| 失败后在队列里的位置 | 隔 **3 张卡** | 卡片计数，不是时间；与上面的时间间隔配合 |

这些常量在 `unit_intraday.py`：`STEP_DELAY`、`RETRY_DELAYS`、`MAX_RETRIES_PER_DAY`、`DAY_END_MARGIN`；
队列卡数在 `unit_fsrs_adapter.py` / `unit_scheduler.py` 的 `RETRY_AFTER_CARDS`。

## 四、一个实际例子（用来校准直觉）

「汉代的学校教育制度 → 中央官学 → 太学」（30 个节点）：

| 时间 | 操作 | 结果 |
|---|---|---|
| 10-24 晚 | 第一次学，记得 | 30 分钟复查 → 通过 → 排到 10-25 |
| 10-25 中午 | 到期复习（第2天），点**困难** | 当天再练（10 分钟） |
| 10-25 中午（重练） | 点**记得** | 先 30 分钟再复查一次；通过后排到 10-26（第3天） |
| 10-26 | 第3天，记得 | 排到 10-28（第5天） |
| 10-28 | 第5天，记得 | 交给 FSRS（前 30 天每次最多翻倍） |

## 五、一直点“记得”会是什么节奏

假设都按时复习、从不点忘记/困难，从 2026-10-26 开始：

| 复习日 | 下一次 | 间隔 |
|---|---|---|
| 10-26 首次学 | 10-27 | 当天 30 分钟复查 |
| 10-27（第2天） | 10-28 | 1 天（固定） |
| 10-28（第3天） | 10-30 | 2 天（固定） |
| 10-30（第5天） | 11-03 | 4 天（FSRS 想排更远，被翻倍上限压到 4） |
| 11-03 | 11-11 | 8 天（上限） |
| 11-11 | 11-27 | 16 天（上限） |
| 11-27 | 12-29 | 32 天（上限；之后完全交给 FSRS） |

有考试冲刺时，超出考期的日期会被拉回考期前，但绝不会被延长。

## 六、睡前复习

「睡前复习」（随心页右侧月亮按钮）把**今天已经评过分的单元**追加到当前队列末尾，再统一过一遍：

- 这些单元的评分**只记录在本轮计划里**，不会写入复习账本，也不会改动到期日或 FSRS 记忆状态；
- 今天还没评分的卡本来就在队列里，它们的评分照常生效；
- 再次点月亮只会追加“今天新评过分、还没进过睡前队列”的卡，不会重复追加；
- 睡前复习卡过学习日 03:00 后自动清掉。

## 七、排期之外、但会影响你看到的日期

- 单元的内容编辑、永久标记增删：**不改变**已获得的到期日和记忆状态；新内容继承最近祖先的进度。
- 删除最后一个标记：单元停用但保留历史；重新标记会继承原来的进度。
- 手动改到期日（复习面板）是独立的写入口，和自动排期不冲突。
- 一次评分只能有一个“有效值”；离开卡片前改判会整体替换，前一次不留排期影响。
- 策略升级（`SCHEDULER_VERSION`）只补写 `early_step` 计数器并盖版本号，**不移动**已经排好的日期；
  新规则从下一次评分开始生效。没有 FSRS 快照的旧单元仍会重放评分历史来建立记忆状态。

## 八、改这些参数去哪里

| 想改什么 | 文件 | 常量 |
|---|---|---|
| 固定期几轮、每轮隔几天 | `unit_fsrs_adapter.py` | `EARLY_LADDER_INTERVALS`、`EARLY_LADDER_STEPS` |
| 从第几档交给 FSRS | `unit_fsrs_adapter.py` | `EARLY_LADDER_MAX_STEP` |
| 前期之后的增长上限 | `unit_fsrs_adapter.py` | `GROWTH_CAP_MAX_PREVIOUS_DAYS`、`GROWTH_CAP_RATIO`、`GROWTH_CAP_MIN_DAYS` |
| 目标保持率 / 最长间隔 | `unit_fsrs_adapter.py` | `build_unit_scheduler(...)` 参数 |
| 当天复查、重练间隔 | `unit_intraday.py` | `STEP_DELAY`、`RETRY_DELAYS`、`MAX_RETRIES_PER_DAY` |
| 一次评分后隔几张卡再出现 | `unit_fsrs_adapter.py` | `RETRY_AFTER_CARDS` |

改完规则后 `SCHEDULER_VERSION` 会变，后端下次启动会对所有单元补写固定期计数器并盖版本号；
成熟单元的已获得排期原样保留，不会被二次放大。
