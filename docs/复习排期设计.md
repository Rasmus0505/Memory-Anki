# 复习排期设计（当前实现）

> 这份文档描述**代码现在真正在做什么**，不是旧方案或计划。改排期规则时同步改这里。
> 对应实现：`apps/api/src/memory_anki/modules/memory/application/`
> （`unit_scheduler.py`、`unit_fsrs_adapter.py`、`unit_intraday.py`）。
>
> 最后更新：2026-10-29（二段定锚 + 受控 FSRS：当天 20 分钟复查 → 第 2 天隔夜检验 →
> 隔夜成功后排 +3 天并移交 FSRS；「困难」从失败改为通过）。

## 一、一句话总览

- **调度单位是「复习单元」**：脑图上的一个永久标记（L1/L2…）及其下游内容。不是单个节点。
- **新卡只有两个固定节点**：当天 **20 分钟**复查一次 → **第 2 天**隔夜检验一次；
  隔夜检验点「记得」→ 排到 **+3 天**并交给 FSRS，点「轻松」→ **+5 天**并交给 FSRS。
- **只有「忘记」是失败**：当天重练（10 分钟 → 1 小时 → 3 小时，最多 3 次）。
- **「困难」是通过**：它只会把下一次间隔压短，绝不当天重练、绝不拉长间隔。
- **学习日 03:00 翻页**：凌晨 0:00–3:00 仍算前一天。

## 二、定锚期（只针对新卡，`early_step = 0`）

| 你的评分 | 单元当前状态 | 下一次什么时候出现 |
|---|---|---|
| 记得 | 第一次学 | 当天先 **20 分钟**复查一次；通过后 → **明天**（第 2 天隔夜检验） |
| 困难 | 第一次学 | 同上（按通过处理） |
| 轻松 | 第一次学 | **免复查**，直接 **+3 天**，定锚期结束 |
| 记得 | 20 分钟复查时 | **明天**（第 2 天隔夜检验） |
| 困难 | 20 分钟复查时 | **明天**（第 2 天隔夜检验） |
| 轻松 | 20 分钟复查时 | **+3 天**，定锚期结束 |
| 记得 | 第 2 天隔夜检验 | **+3 天**（→ 第 5 天），**移交 FSRS** |
| 轻松 | 第 2 天隔夜检验 | **+5 天**（→ 第 7 天），**移交 FSRS** |
| 困难 | 第 2 天隔夜检验 | **+1 天**，留在定锚期再检验一次（不重练） |
| 忘记 | 任何定锚状态 | 当天重练，过后 **+1 天**，重新做隔夜检验 |

补充规则：

- **定锚期只有一次 20 分钟复查**：重练通过**不再**叠一次复查，直接排明天。
- **「轻松」是逃生门**：首次学就点轻松会跳过复查与隔夜检验；复查时点轻松同样直接毕业。
- **定锚期靠计数器**：`early_step`（0 = 定锚期，1 = 已移交 FSRS）。旧数据没有这个值时会先按
  旧的 0–3 四轮计数推断一次，再映射成 0/1（≥1 一律视为已过隔夜检验）。

## 三、FSRS 期（`early_step = 1`）的三条护栏

设上一次实际排到的间隔为 `p`（= 到期日 − 上次评分的学习日）：

| 你的评分 | 新间隔 |
|---|---|
| 忘记 | 当天重练；重练通过后 **+1 天**确认隔夜 |
| 困难 | `clamp(FSRS, 0.8p, p)`，最少 1 天——**绝不拉长**。p=0（重练日）时固定 1 天 |
| 记得 | `p < 10` 时 `min(FSRS, ⌊2.5p⌋)`；`p ≥ 10` 时完全不设限 |
| 轻松 | `p < 10` 时 `min(FSRS, ⌊3.5p⌋)`；`p ≥ 10` 时完全不设限 |

- **任何通过至少排到次日**；间隔 ≥7 天时加一个按单元 ID 计算的 ±5% 确定性抖动。
- **老卡忘记后的恢复**：`p ≥ 14` 时记下「忘记前的原间隔」；隔夜确认（次日及以后任一通过）按
  **困难 25% / 记得 30% / 轻松 35%** 恢复，然后清除该状态。`p < 14` 不走恢复，按正常护栏重建。
- **FSRS 参数**：目标保持率 `0.9`、最长 `365` 天、自身 fuzz 关闭（见下条抖动）。
- **考试冲刺**：只把超出考期的日期**拉近**，绝不延长；失败仍然当天重练。
- **显示档位 `stage_index`**（0/1/3/7/14/30/60/120/240/365）只是兼容投影，不参与排期；
  面板按真实间隔分组。

## 四、分钟 / 小时级间隔（同一天内）

| 场景 | 间隔 | 说明 |
|---|---|---|
| 第一次通过后的复查 | **20 分钟** | 只复查一次；通过后进入第 2 天 |
| 重练通过 | 不复查 | 直接排明天，由隔夜检验确认 |
| 忘记 第 1 次重练 | **10 分钟** | |
| 第 2 次重练 | **1 小时** | |
| 第 3 次重练 | **3 小时** | 当天最后一次 |
| 一天最多重练 | **3 次** | 之后排明天，不在当天反复出现 |
| 学习日结束前 | **15 分钟**内放不下 | 直接排明天（学习日 03:00 结束） |
| 重练卡在队列里的位置 | 到点后**紧跟当前卡** | 只按时间放行；到点前不在队列里 |

这些常量在 `unit_intraday.py`：`STEP_DELAY`、`RETRY_DELAYS`、`MAX_RETRIES_PER_DAY`、`DAY_END_MARGIN`。
到点前 occurrence 保持 `pending` + `available_at`，服务端读取时用 `publish_ready_retries`
放上轨道；前端不自己插卡，只在源卡角标和顶部横幅显示倒计时（`freestyleWaitCopy.ts`）。

## 五、时间线（用来校准直觉）

### 5.1 一路都点「记得」

| 复习日 | 上一次评分 | 下一次 | 这一步的间隔 |
|---|---|---|---|
| 10-26 首次学 | 记得 | 10-26（约 20 分钟后复查） | 当天 |
| 10-26 复查 | 记得 | 10-27 | 明天（隔夜检验） |
| 10-27 第 2 天 | 记得 | 10-30 | +3（定锚期结束，移交 FSRS） |
| 10-30 | 记得 | 11-06 | +7（2.5 倍封顶） |
| 11-06 | 记得 | 11-23 | +17（2.5 倍封顶） |
| 11-23 | 记得 | 由 FSRS 决定 | 上一次 17 天 ≥10，解除封顶 |

### 5.2 第 2 天点了一次「困难」

| 时间 | 操作 | 结果 |
|---|---|---|
| 10-24 晚 | 首次学，记得 | 20 分钟后复查 → 10-25 |
| 10-25 第 2 天 | 点**困难** | **今天过关**，排到 10-26（+1），留在定锚期 |
| 10-26 | 点**记得** | 排到 10-29（+3），移交 FSRS |

### 5.3 点了一次「忘记」

| 时间 | 操作 | 结果 |
|---|---|---|
| 11-05 | 已到第 5 天，点**忘记** | 当天重练（10 分钟），原间隔 7 天 < 14 → 不进入恢复 |
| 11-05 重练 | 记得 | 直接排 11-06（+1），不再复查 |
| 11-06 | 记得 | 按护栏重建（p=1 → 最多 2 天） |

### 5.4 成熟卡点「忘记」

原间隔 60 天：

| 时间 | 操作 | 结果 |
|---|---|---|
| 第 0 天 | 忘记 | 当天重练；记下原间隔 60 天 |
| 第 0 天重练 | 记得 | 排第 1 天（隔夜确认） |
| 第 1 天 | 记得 | **恢复 30%：约 18 天后** |

## 六、睡前复习

「睡前复习」（随心页右侧月亮按钮）把**今天学过的宫殿**追加到当前队列末尾，再统一过一遍。
**一个宫殿就是一个复习单元**，不再按永久标记把宫殿切成多个单元：

- 每座宫殿只出现一张卡，地图显示整座宫殿，评分对整座宫殿只记一次；
- 这些评分**只记录在本轮计划里**，不会写入复习账本，也不会改动任何单元的到期日或 FSRS 记忆状态；
- 今天还没评分的卡本来就在队列里，它们的评分照常生效；
- 再次点月亮只会追加“今天新学过、还没进过睡前队列”的宫殿，不会重复追加；
- 睡前复习卡过学习日 03:00 后自动清掉。

## 七、排期之外、但会影响你看到的日期

- 单元的内容编辑、永久标记增删：**不改变**已获得的到期日和记忆状态；新内容继承最近祖先的进度。
- 删除最后一个标记：单元停用但保留历史；重新标记会继承原来的进度。
- 手动改到期日（复习面板）是独立的写入口，和自动排期不冲突。
- 一次评分只能有一个“有效值”；离开卡片前改判会整体替换，前一次不留排期影响。
- 策略升级（`SCHEDULER_VERSION`）会补写 `early_step` 计数器并盖版本号，**不移动**已经排好的日期；
  新规则从下一次评分开始生效。没有 FSRS 快照的旧单元仍会重放评分历史来建立记忆状态。

## 八、数据与版本

| 列 | 含义 |
|---|---|
| `early_step` | 0 = 定锚期；1 = 已移交 FSRS；NULL = 未记录，按已排间隔推断一次 |
| `lapse_original_interval_days` | 成熟卡忘记前的原间隔（≥14 天才记录） |
| `lapse_started_on` | 记下原间隔的学习日；次日及以后的通过触发恢复并清空 |

`SCHEDULER_POLICY_VERSION = "anchor2-bands-1"`。启动回填（`review_scheduler_switch.py`）：

- 有 FSRS 快照：旧 `early_step 0 → 0`、`1/2/3 → 1`；不移动到期日，只盖版本号。
- 没有 FSRS 快照：重放评分历史（会按新规则重算到期日，这是现有行为）。

## 九、改这些参数去哪里

| 想改什么 | 文件 | 常量 |
|---|---|---|
| 定锚期几个节点、每步几天 | `unit_fsrs_adapter.py` | `ANCHOR_STEP_DAYS`、`ANCHOR_PASS_DAYS`、`ANCHOR_EASY_DAYS`、`ANCHOR_HARD_DAYS`、`ANCHOR_FIRST_EASY_DAYS` |
| 困难/记得/轻松 的护栏 | `unit_fsrs_adapter.py` | `HARD_RATIO_MIN/MAX`、`GOOD_CAP_RATIO`、`EASY_CAP_RATIO`、`CAP_MAX_PREVIOUS_DAYS` |
| 忘记恢复比例 | `unit_fsrs_adapter.py` | `LAPSE_MIN_PREVIOUS_DAYS`、`LAPSE_RECOVERY_RATIO` |
| 目标保持率 / 最长间隔 | `unit_fsrs_adapter.py` | `build_unit_scheduler(...)` 参数 |
| 当天复查、重练间隔 | `unit_intraday.py` | `STEP_DELAY`、`RETRY_DELAYS`、`MAX_RETRIES_PER_DAY` |
| 抖动 | `unit_fsrs_adapter.py` | `FUZZ_MIN_INTERVAL_DAYS`、`FUZZ_RATIO` |

改完规则后 `SCHEDULER_VERSION` 会变，后端下次启动会对所有单元补写定锚计数器并盖版本号；
已生效的排期原样保留，不会被二次放大。
