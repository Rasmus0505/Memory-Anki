# 豆包 AI Agent 大模型训练实习面试准备

## 1. 一分钟自我介绍

我是一名西南财经大学经济学本科生，主修经济学、统计分析和 Python 应用，平时也使用 Excel 做数据整理和分析。我独立维护了一个开源项目 Memory Anki，这是一个基于 FastAPI、React 和 SQLite 的 AI 辅助学习平台。我在项目中负责需求拆解、AI 协同开发、结果验收和测试迭代，设计了提问、解释、出题和纠错等 AI 任务，并实现了结构化结果预览、人工审核、确认应用和运行记录。这个过程让我积累了把开放需求转成明确输入、输出和质量标准的经验，希望将经济学和数据分析背景迁移到 AI Agent 训练与数据质量工作中。

## 2. 高频追问与回答要点

### 为什么想做 AI Agent 训练？

我对“如何把人的判断标准转成模型可执行任务”比较感兴趣。Memory Anki 中，AI 结果不能直接写入题库，而需要经过预览、逐项审核和确认应用。这让我认识到，Agent 训练不仅是让模型生成内容，还包括任务定义、上下文组织、输出格式、质量判断和反馈闭环。

### 你有没有做过大模型参数调优？

目前没有做过系统的模型参数调优，也没有把自己包装成专业模型训练人员。我的实际经验集中在任务设计、Prompt 组织、结构化输出约束、异常处理和结果审核。如果岗位需要，我可以在已有的任务拆解和数据分析基础上快速学习标注规范、评测方法和模型参数含义。

### 你如何判断模型输出质量？

先根据任务定义检查四类指标：事实是否正确、是否覆盖要求、格式是否符合协议、结论是否有充分依据。对出题或修改建议这类结果，再检查来源节点是否正确、是否存在重复或越界内容。系统中先保留预览状态，再由用户逐项接受或拒绝，而不是自动写入。

### Memory Anki 中 AI 流程的具体做法是什么？

请求包含场景、任务类型、上下文、用户要求和模型选项。提问和解释返回文本；出题和纠错要求 JSON 结构。服务端会解析结构化结果，给每个项目附加待审核状态，并记录 Prompt 快照、模型元数据、运行状态、错误和反馈，后续再由用户决定是否应用。

### 为什么要做 OpenAI-compatible 网关？

不同模型服务的请求地址和响应细节可能不同。统一网关后，上层业务只依赖稳定接口，网关负责请求构造、流式响应解析、协议错误、超时、网络异常、限流和服务端错误重试，也方便后续切换模型提供方。

### 你如何避免异步结果写错对象？

每次运行携带稳定的 owner_id 和 operation_id，并保存线程、父运行和重试关系。重复 operation_id 会返回已有记录；结果落库时根据实体和运行身份校验，避免旧请求覆盖新请求或更新到其他学习对象。

### 你在项目中如何使用 AI 编程工具？

我先自己明确需求、边界和验收条件，再让 Codex 或 Claude 协助拆分任务、生成实现和定位问题。生成代码后，我会检查模块依赖、数据流、异常路径和测试结果；关键行为通过测试和实际运行验证。AI 是协作工具，最终的需求判断、代码验收和迭代责任由我承担。

### 你能否完成岗位要求的高频任务？

我会先建立任务模板和检查清单，明确输入、期望输出、禁止事项和判定标准；处理每条任务时保留来源和修改记录，提交前检查事实、逻辑、格式和完整性。如果遇到不确定内容，会标记问题并向负责人确认，而不是凭猜测提交。

## 3. 需要准备的 Excel 案例

- 用筛选、排序和透视表完成一份消费者调研汇总。
- 用查找函数或条件函数完成两张表的数据匹配和异常检查。
- 用图表展示不同用户群体的偏好差异，并用三句话总结结论。
- 说明如何用 AI 辅助生成公式或整理表格，同时人工检查公式逻辑和数据结果。

## 4. 不应主动声称的内容

- 独立完成大模型预训练或微调。
- 已经参与商业化 Agent 标注项目。
- 通过调整 temperature 等参数显著提升模型效果。
- 拥有真实用户量、调用量或题目数量，除非能够提供记录。
