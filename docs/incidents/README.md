# 问题档案（Incident Case Files）

本目录记录**真实发生过的故障**，一个根因一个文件。

## 为什么存在

这个项目里同一个根因已经换过几副面孔回来过（见 0001）。原因不是没人修，
而是**每次修复的结论散落在不同名字的文档里，且互相矛盾**：新的 AI 会话
只读到其中一份，就会做出与另一份相反的决定。

本目录是这些结论的**唯一去处**。写在这里，下一次会话就能一次读懂。

## 规则

1. **一个文件 = 一个故障主题**，不是一症状一个文件。同一主题下可以有多个独立根因（例如 0004 的账本重算 + 冷池打开）；同一根因的不同表现写进同一个文件。
2. **必须能被人看懂。** 第一节用平实语言描述用户看到的现象；技术机制放后面。
3. **必须有证据。** 每条结论都要能指回日志行、实测数字或受控实验。
   区分"已证明"与"推断"——推断要明确标注。
4. **必须有防复发措施。** 没有守护测试/门禁的修复不算完成。
5. **必须诚实登记未修复部分。** 否则下一个人会以为已经解决。
6. 与本目录结论冲突的旧分析文档，应合并进来并标注取代关系，不要两份并存。
