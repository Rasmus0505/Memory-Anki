# 题库文本乱码修复

> 最后核对：2026-11-07。  
> 适用对象：题目解析、选项、宫殿脑图节点文本里的 OCR / 字体编码残渣。

## 问题长什么样

| 现象 | 例子 | 来源 |
|---|---|---|
| Latin-1 乱码串 | `学校教育制度(核心)ìîíïïïïïï公立教育` | PDF 树形图的连线字符被按错误编码解码 |
| 表格框线粘在选项尾 | `形成更加成熟更加定型的制度 ┐` | 从表格里复制选项时带上了边框 |
| 页码粘进句子 | `北京是亚洲的66城市` | OCR 把页脚数字并进了正文 |
| 漏字后留下残句 | `形成若干个4人或人合作学习小组` | OCR 丢字，原文是「4 人合作学习小组」 |
| 替换符 `�` | `科学的态度与精神` 被写成 `科学的态��与精神` | UTF-8 字节损坏，常见于脑图节点 |
| 表格/知识树被压平 | `水平共同特征阶段阶段特征前习俗水平……` | PDF 表格或脑图被抽成一段无标点长串，层级全丢 |

同一批导入的题和脑图节点会共享这些残渣；只修当前可见的那一道，回收站或旧版本里仍会留着同样的串。

## 修复脚本

```bash
# 干跑：只打印将改什么，不写库
python tools/question-repair/repair_text_corruption.py

# 写库：先 checkpoint + 整库备份，再在一个事务里更新
python tools/question-repair/repair_text_corruption.py --apply
```

脚本里只有**逐条核对过的显式清单**，不做猜测式批量替换：

- `ANALYSIS_REWRITES`：被压平的表格/知识树，按原表重排成多行
- `ANALYSIS_REPLACEMENTS`：解析里的定点替换（页码、漏字）
- `OPTION_TRAILING_GLYPHS`：选项尾部框线
- `PEG_NAME_FIXES`：脑图节点名
- `PALACE_DOC_FIXES`：`palaces.editor_doc` 与 `palace_versions` 快照里的同一批乱码

备份文件名形如 `memory_palace.before-text-repair-20261107-212319.db`，和数据库同目录。

## 判定口径

1. **只修活跃内容**：`palace_quiz_questions.deleted_at is null`、未删除的宫殿与其当前版本。软删的重复题保留墓碑，不为了好看去改删除记录。
2. **保留原意**：只还原乱码对应的原文，不顺手改写解析风格、不补写空解析。
3. **写前写后都自检**：脚本会扫描活跃题的题干、选项、解析，遇到 Latin-1 乱码、私用区字符、替换符、框线字符就报出来。
4. **API 复核**：写库后可直接查
   - `GET /api/v1/palaces/{palace_id}/quiz-questions`
   - `GET /api/v1/palaces/{palace_id}`

## 复查 SQL

```sql
-- 活跃题里的同类乱码（应返回空）
select id, palace_id
from palace_quiz_questions
where deleted_at is null
  and (
    stem glob '*[À-ÖØ-öø-ÿ]*'
    or options_json glob '*[À-ÖØ-öø-ÿ]*'
    or analysis glob '*[À-ÖØ-öø-ÿ]*'
    or stem like '%�%'
    or options_json like '%�%'
    or analysis like '%�%'
    or stem glob '*[│├└─┌┐┘┬┴┼]*'
    or options_json glob '*[│├└─┌┐┘┬┴┼]*'
    or analysis glob '*[│├└─┌┐┘┬┴┼]*'
  );
```

注意：`×`、`÷` 是解析里正常的对错标记，正则要排除；`√` 不在 Latin-1 范围内，不受影响。
