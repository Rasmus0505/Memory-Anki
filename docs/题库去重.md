# 题库去重（大模型语义判重）

最后核对：2026-11-06　流水线：`tools/question-dedup/`

## 一句话

按「同一道题」的语义把题库里的重复题找出来，软删多余的，每条宫殿至少留一条，答案互相矛盾的不删、挂起交人工。

## 为什么会有重复

题库来自多本教辅、多个老师（凯程 / 冬青 / 丹丹 / 腿姐 / 肖秀荣）和多次导入，同一道 311、333 真题会被不同来源各录一遍；导入脚本还曾把每道选择题额外生成一条「简答题」副本——题干相同、没有选项、参考答案就是正确选项那几个字。这两类占了全部重复的九成以上。

## 判定口径

**算重复**
- 题干去掉来源前缀（`【丹丹老师｜自命题】` 等）、空白、标点后相同，且答案实质相同。
- 选择题版 + 简答题版，简答参考答案等于选择题正确选项。
- 跨来源同题：同一道真题被不同老师录入；腿姐《刷题计划》与《拆真题》的孪生题。

**不算重复**
- 同一知识点换问法：问「谁提出」vs 问「意义 / 局限」。
- 同一材料不同问题：同案例问「用了什么德育方法」vs「体现什么原则」。
- 选项不同导致答案不同；单选与多选选项集合不同。
- 只改数字、人名的变式题。

**保留谁**
- 有作答记录 > 有选项 > 有解析 > 导入更早。
- **每个宫殿至少留一条**：跨宫殿的同题不合并，避免某个宫殿被抽空。这是唯一偏离「全库唯一」的地方。

## 流程

1. `export_questions.py` 导出在世题目。
2. `build_clusters.py` 归一化题干 → 同题干 / 同选项同答案成簇 → 同科目 char 2–4 gram TF-IDF 余弦 ≥0.70 再成簇（并查集）。
3. `classify.py` 把「题干完全相同且答案一致」的簇直接定案，其余生成批次交大模型。
4. 大模型按 `JUDGE_BRIEF.md` 逐簇判定，写 `verdicts/batch-*.json`。
5. `validate_verdicts.py` 校验组数、越界、又删又留。
6. `apply_plan.py` 合并判定（并查集处理「A 组留 X、B 组删 X」的链）→ 按宫殿选唯一幸存者 → 校验 → 整库备份 → 软删 → 回滚清单。
7. `build_batches2.py` + `residual_fix.py` 补漏：低相似度漏网对、跨宫殿合并漏掉的选/简双胞胎。

## 不变量

- **只写 `deleted_at` / `updated_at`**，与 API 的 `commit_deleted_questions` 完全一致；不删行、不动绑定、不动作答记录。
- **写库前整库备份**，并输出 `rollback-*.json`；恢复语句 `update palace_quiz_questions set deleted_at = null where id in (...)`。
- **校验不过拒绝写入**：keep/drop 越界、同一题被判删多次、又删又留，都会中止。
- **答案冲突不自动删**：只标 `conflict`，列进报告。

另清理 72 道题尾部粘着的下一题题号、页码与题型标签（OCR 分页错位），只截断脏字、不动选项 id 与答案。逐学科数字、核对结论、剩余数据问题见 `deliverables/题库去重-2026-11-06.md`。

## 下次加题库时

新导入的题目如果又带「选择题 + 简答题副本」，直接跑一遍流水线即可；建议同时在导入环节拦截：简答题的 `reference_answer` 等于同宫某选择题选项时，不入库。
