# 导图与文章统一工作区实施计划

## 已确认的产品范围

- 工具栏提供思维导图 / 文章切换；文章所见即所得编辑，支持 Markdown 输入快捷方式。
- 标题和知识点列表项对应稳定 UID 节点；正文、图片、表格、公式、代码块归属节点，可多段。
- 同一文档、同一保存链路、同一撤销历史；切换保留定位，手机优先阅读并显式进入编辑。
- 支持 Markdown 创建宫殿、插入当前节点、更新原导出宫殿、替换宫殿；导入先预览，危险删除沿用绑定保护。
- 导出通用 Markdown，以及包含 Markdown、附件、文档身份和关联元数据的完整包。外部修改发生身份歧义时不得猜测关联。
- 文章支持关联题目查看与练习、绑定管理、已有学习标记、遮挡回忆、返回对应导图节点。
- 长文目录与搜索；文章不折叠章节，用缩进和层级线表达结构。视图偏好按设备记忆，阅读进度可接续，阅读中不主动跳转。
- 冲突保留双方版本，安全部分合并，歧义明确选择；结构变更尽量保留现有布局并局部调整。

## 架构决定

1. 文档 owner 仍为 content/domain/mindmap-document-entity；新增纯文章投影与变更规则。正文采用受限结构化富文本 JSON，旧 text/note 不做破坏性迁移。
2. MindMapEditorSurface 内组合文章界面，沿用 useMindMapEditHistory 与宿主 onEditorStateChange。文章不另建宫殿文档保存链路；附件上传和阅读进度使用 content 自身的 owner-bound API 适配。
3. 富文本使用 Tiptap；编辑框拥有输入/IME/选区，文档命令拥有 UID、子树结构和关联。纯文档层不依赖 Tiptap。
4. 阅读动作通过既有 capability 与宿主回调组合；scopeBranchUid 只限制投影和操作，不保存截断的可见树。
5. 设备视图偏好与同步阅读锚点分开保存；必须使用明确的文档 owner 身份，不能使用可能重复的根 UID。
6. 导入导出通过 content/produce 的公共边界组合，资源仅引用可移植标识，不写入机器绝对路径。完整包必须检查大小、格式、路径和引用。
7. 修复草稿恢复的 baseEditorFingerprint 检查，再接入新编辑方式。冲突和异步动作校验 owner/operation，不能跨文档应用。
8. Syncthing 仍在应用外同步；本功能不实现文件同步，也不支持两台电脑同时写同步 SQLite。应用版本冲突与文件导入冲突需要显式解决。

## 内部实施顺序

- A：文档投影、结构命令、富正文验证；草稿恢复冲突保护。
- B：文章编辑与阅读、共用历史、工具栏、手机布局、定位和学习动作。
- C：Markdown 与完整包转换、四种导入预览/应用、附件与关联恢复。
- D：跨设备阅读锚点、差异合并与版本恢复、性能与无障碍。
- E：架构规则、单测/集成/封闭 E2E、完整质量门禁、构建和启动器冒烟。

A–E 实施与集成验证已完成。此文件记录设计依据；实际门禁结果与明确支持边界见 [article-workspace-validation.md](./article-workspace-validation.md)，日常操作见 [使用指南](../article-workspace-guide.md)。

## 验收重点

- 双视图编辑立即一致，UID 与题目关联不因文字修改或章节移动改变。
- 增删章节、缩进/提升层级、撤销/重做在两种视图间连贯；删除题目绑定节点有保护。
- 中文输入法、移动端键盘、切换、关页恢复不会丢字或跨文档写入。
- 旧导图保持可读和可编辑；深层级不无限缩窄手机内容。
- 富内容粘贴与文件导入清理危险内容；图片、公式、表格、代码可以编辑并往返。
- 草稿过期、HTTP 版本冲突、导出后外部修改重导入保留双方内容。
- 阅读进度不污染文档撤销历史，也不在当前阅读中突然移动视口。
- 测试不连接真实学习数据库，E2E 采用既有 hermetic fixtures。
