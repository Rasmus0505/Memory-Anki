# 颜色字面量只减不增

`tools/check_architecture.py` 扫描 `apps/web/src` 内的 `.ts`、`.tsx`、`.css`，对每个文件记录颜色字面量数量。基线在同目录的 `color-literal-baseline.json`。

## 规则

- `apps/web/src/styles/foundation.css` 是颜色令牌定义源，不计入预算。
- 文件名包含 `.test.` 和路径包含 `/test/` 的测试文件不计入预算。
- 识别十六进制颜色、数字开头的 `hsl/hsla/rgb/rgba/oklch/oklab`，以及列明的 Tailwind 色阶类。`var(--token)` 等令牌引用不计数。
- 文件超过预算或新文件出现字面量，检查失败。应复用语义令牌，不应提高预算来绕过检查。
- 清理使数量下降时，同步下调该文件基线；降为零或删除文件时删除对应条目，不能留着以后复用的额度。
- 缺失、损坏或类型错误的基线会报错，不会静默当作空基线。

2026-11-09 初始基线为 **66 个文件、773 处**。这是一份存量清单，不代表这些颜色已符合设计规范，也不要求一次性修改全部旧页面。

## 验证

运行 `python tools/check_architecture.py`；门禁自身由 `tools/test_color_literal_ratchet.py` 的正反例验证，已接入 `tools/quality_gate.py` 与 CI。测试覆盖正常匹配、非颜色字符串、令牌及测试文件豁免、预算增减、删除文件和非法基线。必须保留直接检查匹配数量的用例：单纯对当前代码生成基线，会让失效的扫描器和空基线一起假通过。

## 边界

这是有限的文本扫描，不是 CSS/TS 语法分析器。注释中的匹配也计数，动态拼接、命名颜色和未列出的颜色函数不在覆盖范围内。同一文件删一个颜色再加另一个，数量不变，也不会被拦截。新增令牌和等量替换仍需审查语义与实际界面；不能把门禁通过当作视觉一致性的证明。
