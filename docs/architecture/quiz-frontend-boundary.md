# Quiz Frontend Boundary

Quiz question contracts, API wrappers, runtime state, reusable answer interaction UI, attempt orchestration, and result feedback belong to `modules/quiz`. These capabilities are shared by Palace Quiz, Freestyle, and Review flows and must not live inside a page-oriented route.

```text
pages/palace-quiz -> modules/quiz/public.ts
modules/practice/ui/freestyle -> modules/quiz/public.ts
modules/practice/ui/review -> modules/quiz/public.ts
```

The Palace memory lookup dialog composes Palace data, review feedback, and the mind-map editor, so it belongs to `widgets/palace-memory-lookup`. Palace Quiz and Freestyle consume the widget without importing one another. When a caller passes the current question’s bound node uids (`focusNodeUid` / `focusNodeUids` from `collectMemoryLookupFocusNodeUids`), the dialog keeps the full palace `editor_doc` and visually centers the deepest bound node via `focusRequestNodeUid` (`resolveMemoryLookupFocusNodeUid`). A default palace-root binding must not win over a deeper bound card. It must not re-root or clip the tree to the bound node. The lookup header offers 查看模式, 翻卡模式, and 编辑模式. 编辑模式 edits that same full palace document and autosaves through the palace editor (`palace_edit_autosave` plus `expected_editor_fingerprint`); leaving edit mode flushes the pending document and reconciles review units. It must not save a clipped subtree. Node-bound question badges use `widgets/node-bound-quiz`. Freestyle toolbar 做题 uses `widgets/freestyle-scope-quiz`: same answering chrome, question list from the saved feed palace range plus `overlay_question_range` (`due` / `all`). Durable overlay membership and answered drafts live on round-plan `overlay_quiz` and survive PWA reload. The SPA `quizSessionProgress` mirror is shared across node-bound badges, the overlay, and Palace Quiz practice for the SPA lifetime only; toolbar 做题 re-seeds it from `overlay_quiz` after reload. 「再来一轮」 clears both. When a palace’s review units in the round are all scored, the UI asks before dropping that palace’s overlay 已做. All three surfaces show 标记 / 取消标记. Marking writes `marked` and does not schedule review or auto-advance. Marked question numbers on the index rail use a rose fill. It must not switch `training_mode` or open `QuizLauncher`. New cross-scene quiz primitives should be added to the Quiz entity; new multi-feature visual composition should be added to a widget or page.

Multiple-choice active-recall rewriting (选择 / 主观) lives in the Quiz entity: `quizAnswerMode`, `mcqSubjectiveRewrite`, `QuizQuestionStem`, `QuizQuestionInteraction`, and the `quiz_answer_mode` client preference. Switching to 主观 rewrites the stem so it does not depend on options and stays at equal or higher recall difficulty (not a shorter recognition prompt). The 选择 / 主观 toggle stays available after either presentation is answered. A subjective submit does not close the choice attempt (`isQuizChoiceAttemptClosed` is a selected option, not the shared `resolved` flag), and a choice attempt does not close the subjective draft. After a converted multiple-choice submit, the entity lists the original options without marking the correct choice, and writes the reference answer as the first line of the analysis. Enter submits the short-answer attempt; the interaction surface restores keyboard focus when the question or mode changes so hosts do not leave submit shortcuts stuck on 下一题. Freestyle cards, node-bound quiz dialogs, and Palace Quiz practice consume that primitive; they must not reimplement the toggle, stem rewrite, short-answer presentation, or submit shortcuts.

Do-question overlays (`widgets/freestyle-scope-quiz`, `widgets/node-bound-quiz`) paginate the top question-number rail through `QuizQuestionIndexPager`. One page is one measured row: pill size stays fixed (`size-7`) and `quizIndexPageCapacity` decides how many fit; the unmeasured fallback is 20. The row label is `第 {page}/{pages} 页 · 第 {current}/{count} 题` (no start–end range). While that pager is visible, hosts keep 已答 and palace context in the dialog description and must not repeat the current-question counter there. Hosts must not render the full round-button grid inline.

Do-question shortcuts live in the Quiz entity: `quizShortcuts`, `QuizShortcutSettingsSection`, and `useQuizAnsweringShortcuts`, persisted as the `quiz_shortcuts` client preference. Freestyle 做题 shows that section inside the top-left 配置 panel. Node-bound 关联题目 opens the same section from its top-left 快捷键 control. Both dialogs share one map. Mark defaults to ArrowUp and toggles once per key press; key repeat must not toggle again. Question navigation, option movement, digit and letter selects, and Enter submit stay configurable. ArrowUp is not also the previous-option default. While either dialog is open, ArrowUp and ArrowDown must not page the freestyle feed underneath. Hosts must not keep a second keydown listener for these actions.

Answer-dialog font scale lives in the Quiz entity: `quizFontScale`, `useQuizDialogFontScale`, `QuizFontScaleBody`, `QuizFontScaleHint`, and the `quiz_font_scale` client preference. The node-bound dialog and the freestyle 做题 dialog share one percent (70–180, step 10, default 100). Ctrl+wheel upward enlarges and Ctrl+0 restores 100%; the hook owns that gesture (`passive: false` so the browser does not zoom the page) and shows the percent briefly. Hosts apply `QuizFontScaleBody` only to the 题目正文 (stem, options, inputs, analysis). The header, question-number rail, badges, and footer stay at the default size. Hosts must not attach their own wheel listener or store a second scale.

## Application Quiz Launcher

The global quiz launcher is mounted by `AppProviders` and coordinates Palace metadata, AI configuration, background generation tasks, navigation, and Palace Quiz generation. It belongs to `widgets/quiz-launcher`, while question generation and interaction stay in `modules/quiz`. Palace View, Palace Edit, and Review flows consume the widget context without importing quiz internals.

Review feedback reward state and reusable feedback orchestration live in `modules/memory/domain/review-entity`, because Palace practice, Review flows, and lookup widgets share them. Route code must not recreate these models under a page.
