# Surface brief：随心 · 本轮结算

> 由 `/impeccable shape` 产出：只写“要做什么、怎么成立”，不写代码。
> 目标组件：`apps/web/src/modules/practice/ui/freestyle/components/FreestyleRoundSettlement.tsx`
> 假设：本轮没有交互问答；以下判断来自代码、PRODUCT.md 与既有使用记录，标注为“推断”的部分待用户确认。

## 1. 任务与受众

- **谁**：刚翻完一轮卡（10–40 张）的学习者，通常在晚上，注意力已经开始下降。
- **来的时候想要什么**：确认“这一轮算不算完成”，以及“明天还要不要来”。
- **模式**：Persuade（让人愿意收下这一轮，并愿意明天再来），不是 Read。

## 2. 结果与证据

- **主结果**：一眼看懂本轮翻了多少、通过了多少、还剩多少；知道下一步只有两个选择（收下 / 清空做题进度）。
- **成功标准**：
  - 3 秒内能回答“我这轮学得怎么样”；
  - 不需要滚动就能看到“明天还有多少”；
  - 关闭结算后不会怀疑数据没保存。
- **真实证据**：本轮已评分单元数、新学/复习/重练拆分、宫殿总进度、今日剩余、明日到期、保存状态。

## 3. 选定的方向

- **结构论点**：结算不是报表，是一张**盖章的收据**。最重要的数字（本轮评分单元数）最大，其次才是三格拆分和总进度。
- **视觉权威**：沿用「纸与灯」的舞台版本（暖黑底、米白字、琥珀强调），但把“完成”做成一个明确的印记，而不是再来一个进度环。
- **焦点时刻**：数字落定的那一下（数字滚动 + 一枚朱砂/琥珀的完成印记），全页只安排这一次动效。
- **实现后果**：保留现有数据与保存逻辑，只重排信息层级与完成印记。

## 4. 范围与边界

- **范围**：结算面板本身（标题、数字、三格、总进度、保存状态、两个动作）。
- **不动**：评分流程、保存协议、清空做题进度的语义、跳过结算的行为。
- **反目标**：不做烟花/彩带雨；不做第二套“游戏化”语言；不把结算做成营销页。

## 5. 状态与数据范围

- 本轮 0 个单元 / 1 个 / 40 个；宫殿 1 座 / 200 座。
- 保存中、保存失败（可重试）、已保存。
- 有做题进度可清空 / 无；已清空。
- 手机 390px：不滚动也能看到主数字与“明天”一行。

## 6. 交互与布局

- 自上而下：完成印记 + 本轮数字 → 三格拆分 → 宫殿总进度 → 明天/剩余一行 → 保存状态 → 两个动作。
- 手机上三格保持一行；两个动作保持并排，主次分明。
- 动效：数字 600ms 落定，印记 700ms 压印；`prefers-reduced-motion` 下全部静态。
- 反馈：保存失败时动作区上方出现可重试的明确提示，不遮挡主数字。

## 7. 约束与开放决定

- 约束：舞台不跟随浅色主题；数据全部来自现有 props；不新增网络请求。
- 开放决定（需用户确认）：
  1. 完成印记用“朱砂印章”还是“琥珀灯印”？
  2. 结算是否保留“清空做题进度”这个入口，还是收进次级菜单？
