# Memory Anki — Game Feel / Juiciness 设计方案

> 适用对象：Web PWA「思维导图记忆宫殿 + 翻卡复习」应用
> 技术背景：React + TypeScript，SVG/Canvas 渲染思维导图节点与连线，翻卡 3D flip，已有 `cue()` facade 统一管 motion/audio/haptics
> 目标：在不干扰学习效率的前提下，通过 game feel 设计提升操作反馈感、节奏感与成就感

---

## 1. 权威 Game Feel 理论框架与映射

### 1.1 核心框架来源

| 来源 | 核心概念 | 对本项目的启示 |
|------|----------|----------------|
| **Juice it or Lose It**（Martin Jonasson & Petri Purho, GDC 2012） |  juice = 每个操作都应有「过度」的视听反馈；关键原则：**让按下按钮本身变得有趣**、**奖励每一个玩家行为**、**用效果强化状态变化** | 每次点击/翻卡/标记掌握都应有即时、多感官的确认反馈 |
| **Game Maker's Toolkit**（Mark Brown 系列视频） |  反馈密度、动画十二原则在游戏中的运用（squash & stretch, anticipation, follow-through）、**清晰优于华丽** | 动效应服务于信息传达（对/错/掌握状态），而非纯装饰 |
| **Steve Swink《Game Feel》**（2008） |  输入→响应延迟（input latency）、动画时长与节奏、上下文环境（context）如何影响手感；核心指标：响应时间 < 100ms 感觉即时 | 所有交互动画总时长（press → 视觉确认）应控制在 100ms 内 |
| **《The Art of Game Feel》**（2023, Steve Swink 等） |  将 game feel 拆解为可操作的维度：空间感（spatial）、时间感（temporal）、声音（aural）、触觉（tactile）、表现（presentational） | 每个维度都可独立调参，组合成完整的反馈体验 |

### 1.2 可操作原则 → 非游戏效率应用映射

| 游戏原则 | 原始含义 | 映射到 Memory Anki |
|----------|----------|-------------------|
| **即时确认（Immediate Affordance）** | 按下按钮立刻有视觉/声音反馈 | 点击节点 → 100ms 内出现按压缩放 + 声音/震动 |
| **状态强化（State Reinforcement）** | 用夸张效果标记重要状态变化 | 「掌握」卡片 → 绿色粒子爆裂 + 上升音效 + 震动 |
| **节奏感（Rhythm & Flow）** | 连击、连锁反应维持心流 | 连续答对 → 间隔渐短的级联音效 + 卡片微加速 |
| **过度反馈（Over Feedback）** | juice 比"刚好"多一点更爽 | 每次翻卡都有轻微 whoosh + 纸牌摩擦声 |
| **十二动画原则（12 Principles）** | squash & stretch, anticipation, follow-through | 节点入场：先缩后弹（anticipation → overshoot → settle） |
| **空间一致性（Spatial Consistency）** | 效果应发生在交互原点 | 粒子从被点击卡片中心爆发，而非屏幕中心 |
| **可学习性（Learnability）** | 反馈应帮助玩家理解规则 | 「遗忘」卡片红色抖动 → 用户立即理解"这个没记住" |
| **可关闭性（Optional Intensity）** | 难度/效果强度可调 | 提供「动效强度」设置：完整 / 精简 / 关闭 |

## 2. Web 端成熟库与项目调研

### 2.1 动效库对比与推荐

| 库 | 现状 | 优势 | 劣势 | 适用场景 |
|----|------|------|------|----------|
| **motion**（原 framer-motion） | ✅ 活跃维护，~34k stars，2024 年从 framer-motion 更名为 motion，由 Motion Division 维护 | 声明式 API、layout 动画、`AnimatePresence` 处理元素进出、SVG 动画支持好 | 包体积较大（~50kb gzip） | **首选**：节点/卡片级交互动画 |
| **react-spring** | ✅ 活跃维护，~29k stars | 物理弹簧引擎，手感真实，支持 imperative 控制 | 学习曲线较陡，API 不够直觉 | 需要物理惯性的场景（如拖拽、弹性列表） |
| **GSAP** | ✅ 业界标杆，功能最全 | 时间轴控制、ScrollTrigger、MorphSVG 等插件生态 | 体积大，React 集成需额外封装（@gsap/react） | 复杂时间轴动画（如连击庆祝序列） |
| **popmotion** | ⚠️ 维护放缓 | 纯函数式动效工具集 | 社区活跃度下降 | 不推荐新项目使用 |
| **auto-animate** | ✅ 轻量 | 一行代码实现列表动画，零配置 | 控制能力有限 | 简单列表重排（如卡片队列） |
| **FLIP 技术** | ✅ 通用模式 | 布局变化前后记录位置，用 transform 模拟移动 | 需手动实现或使用库封装 | 思维导图节点重排、卡片队列 |

### 2.2 Material 3 Motion 规范关键参数

Material 3 提供了经过验证的动效时长与缓动曲线：

| 类型 | 时长 | 缓动曲线 | 用途 |
|------|------|----------|------|
| **Standard** | 200–300ms | `cubic-bezier(0.2, 0, 0, 1)` | 常规元素移动、淡入淡出 |
| **Emphasized** | 350–500ms | `cubic-bezier(0.05, 0.7, 0.1, 1)` | 显著状态变化（如翻卡） |
| **Emphasized Accelerate** | 200–250ms | `cubic-bezier(0.3, 0, 0.8, 0.15)` | 元素离开屏幕 |
| **Emphasized Decelerate** | 250–300ms | `cubic-bezier(0.1, 0, 0, 0.2)` | 元素进入屏幕 |
| **Spring（物理弹簧）** | 无固定时长 | stiffness: 170, damping: 26 | 弹性效果、 overshoot |

### 2.3 触觉反馈库（Haptics）

| 方案 | 说明 | 推荐度 |
|------|------|--------|
| **navigator.vibrate() 原生封装** | Web 标准 API，无需外部库；支持 `vibrate(200)` 或 `vibrate([100, 50, 100])` 模式 | ✅ 首选，PWA 可直接使用 |
| **capacitor-haptics** | 需 Capacitor 包装，可调用原生 Taptic Engine / VibrationEffect | ⚠️ 若未来打包原生应用可考虑 |
| **@material/web ripple** | Material 涟漪效果含触觉集成 | 可参考其触发模式 |

**推荐**：在 `cue()` facade 内部封装 `navigator.vibrate()`，自动检测支持性（`"vibrate" in navigator`），iOS Safari 不支持时优雅降级为仅视觉反馈。

## 3. 性能与无障碍约束

### 3.1 性能准则

| 准则 | 说明 | 在本项目中的应用 |
|------|------|-----------------|
| **仅使用 transform 和 opacity 做动画** | 触发合成器线程，避免主线程阻塞 | 节点移动用 `translate`，缩放用 `scale`，避免 `width/height/top/left` |
| **避免 layout thrash** | 不在动画循环中读写交错（forced synchronous layout） | FLIP 实现时先读取布局，再统一写入 transform |
| **使用 `will-change` 谨慎提示** | 提前告知浏览器优化目标 | 仅对频繁动画的元素（如当前翻中的卡片）添加 `will-change: transform` |
| **粒子用 Canvas 或 WebGL** | DOM 粒子数量 >50 时性能骤降 | 粒子数量 ≤ 30 用绝对定位 div；> 30 用 Canvas 2D |
| **减少重绘区域** | 使用 `contain: layout paint` 或 `content-visibility` | 思维导图大画布使用 `contain` 隔离节点重绘 |
| **音频用 WebAudio 预加载** | 避免每次播放重新解码 | `cue()` 初始化时预加载常用音效 buffer |

### 3.2 无障碍（a11y）约束

| 准则 | 实现 |
|------|------|
| **尊重 `prefers-reduced-motion`** | 通过 `window.matchMedia("(prefers-reduced-motion: reduce)")` 检测；开启时：所有动画时长降至 50ms 以下、禁用粒子、禁用视差、禁用自动播放 |
| **提供手动关闭选项** | 设置页提供「动效强度」滑块：完整 / 精简 / 关闭 |
| **颜色对比度** | 状态色（红/绿/黄）需满足 WCAG AA（4.5:1），颜色不作为唯一信息载体（配合图标/文字） |
| **震动反馈不干扰** | 震动时长 ≤ 200ms，强度适中；提供关闭选项 |
| **屏幕阅读器兼容** | 动画不改变 DOM 顺序，aria-live 区域用于播报「答对/答错/已掌握」 |

## 4. 效果强度分级表

| 事件级别 | 触发时机 | 时长 | 缓动曲线 | 声音类型 | 震动 | 粒子/特效 |
|----------|----------|------|----------|----------|------|-----------|
| **微小（Micro）** | 按钮按压、悬停、节点聚焦 | 100–150ms | `cubic-bezier(0.2, 0, 0, 1)` | 无或极轻 tick（< 50ms） | 无或 10ms 微震 | 无 |
| **小（Small）** | 翻卡、标记「认识」、展开节点 | 200–300ms | `cubic-bezier(0.05, 0.7, 0.1, 1)`（emphasized） | 纸牌 whoosh（80ms）或轻确认音 | 30–50ms 短震 | 无或 5–10 粒微光 |
| **中（Medium）** | 标记「掌握」、完成一个宫殿分支、连击 ≥ 3 | 350–500ms | `cubic-bezier(0.05, 0.7, 0.1, 1)` + 弹性回弹 | 上升琶音（三音）或 coin collect | 100ms 中震 | 15–25 粒彩色粒子 |
| **大（Large）** | 完成整个宫殿、连续答对 10+（大连击）、等级提升 | 600–900ms | 多段：加速 + 减速 + 弹性 settle | 庆祝和弦 + 上升音阶 + 低音强调 | 200ms 长震 或 `[100, 50, 100]` 双震 | 30–50 粒全屏粒子 + 屏幕微震 + 节点发光脉冲 |

## 5. 具体参数推荐

### 5.1 按压反馈（Press / Tap）

| 参数 | 值 | 说明 |
|------|-----|------|
| scale 按下 | 0.96（96%） | 微缩给予"被按下"感 |
| scale 释放回弹 | 1.04 → 1.0（overshoot） | 用 spring（stiffness: 500, damping: 15）模拟回弹 |
| 时长 | 按下 80ms，回弹 200ms | 按下快、回弹稍慢，模拟物理惯性 |
| 阴影变化 | 按下时阴影缩小/加深 | 配合 scale 强化立体感 |

### 5.2 翻卡（3D Flip）

| 参数 | 值 | 说明 |
|------|-----|------|
| 总时长 | 300–400ms | 过快看不清，过慢感觉拖沓 |
| 缓动（前半） | `cubic-bezier(0.3, 0, 0.8, 0.15)`（accelerate） | 卡片离开视线时加速 |
| 缓动（后半） | `cubic-bezier(0.1, 0, 0, 0.2)`（decelerate） | 新面进入时减速，有"落下"感 |
| 旋转轴 | Y 轴 180° | 经典水平翻转 |
| 阴影 | 翻转时阴影动态变化（前半加深，后半变浅） | 模拟光线变化 |
| 声音 | 纸牌 whoosh（前半）+ 轻落纸声（后半） | 两段式声音匹配两段动画 |

### 5.3 卡爆裂粒子（Card Burst）

| 参数 | 值 | 说明 |
|------|-----|------|
| 粒子数量（掌握一张卡） | 15–25 粒 | 视觉显著但不阻塞 |
| 粒子数量（大连击/完成宫殿） | 40–60 粒 | 升级为全屏庆祝 |
| 粒子大小 | 3–8px | 混合大小更有层次 |
| 粒子形状 | 圆形 + 少量星形/纸屑形 | 彩色纸屑比纯圆点更"庆祝" |
| 初速度 | 200–400 px/s | 中等速度，不刺眼 |
| 重力加速度 | 800 px/s² | 模拟自然下落 |
| 消散方式 | scale → 0 + opacity → 0 | 避免硬消失 |
| 生命周期 | 600–900ms | 与"中"级别动画时长匹配 |
| 颜色 | 主题色 + 金色/白色高光 | 与"掌握"状态绿色区分，避免红绿混淆 |

### 5.4 连击放大策略（Combo Scaling）

| 连击数 | 效果 | 参数 |
|--------|------|------|
| 1–2 | 基础确认 | 标准音效 + 无粒子 |
| 3–5 | 轻庆祝 | 音调 +100 cents（半音），5 粒粒子，卡片微发光 |
| 6–9 | 明显加速 | 音调 +200 cents，15 粒粒子，翻卡时长 -20ms（260ms），卡片边缘金色描边 |
| 10+ | 大连击模式 | 音调 +300 cents，全屏粒子爆发，翻卡时长 -40ms（240ms），屏幕轻微震动，节点脉动发光 |
| 连击中断 | 回落反馈 | 音调骤降，粒子停止，屏幕微暗 200ms |

**关键原则**：连击加速应有限度，翻卡时长最短不低于 240ms，避免用户无法阅读卡片内容。

## 6. 实施建议与 cue() facade 集成

### 6.1 cue() facade 设计建议

```
cue({
  level: "small" | "medium" | "large",
  origin: { x, y },           // 效果原点（粒子/震动中心）
  motion: { ... },            // 动画参数（时长、缓动、scale 等）
  audio: { type, pitch },     // 音效类型 + 变调
  haptics: { pattern },       // 震动模式
})
```

- **自动降级**：`prefers-reduced-motion` 开启时，`cue()` 内部自动将 motion 时长设为 50ms、audio 音量 -50%、haptics 关闭
- **优先级队列**：避免同时触发多个"大"级效果导致性能问题；连续快速操作时，后一个"微小"效果可覆盖前一个
- **预加载**：初始化时预加载所有音效（建议 8–10 个短音效，总大小 < 200KB）

### 6.2 推荐音效清单

| 音效 | 用途 | 时长 | 类型 |
|------|------|------|------|
| tick | 按钮按压 | 30ms | 短促电子音 |
| whoosh | 翻卡前半 | 100ms | 风声/纸牌 |
| flip_land | 翻卡后半 | 80ms | 纸张落下 |
| correct | 答对 | 150ms | 上升两音 |
| master | 掌握 | 300ms | 三音琶音 + 和声 |
| combo_up | 连击升级 | 200ms | 快速上升音阶 |
| wrong | 答错 | 200ms | 低沉两音下降 |
| burst | 粒子爆发 | 400ms | 彩带/爆炸声 |
| complete | 完成宫殿 | 800ms | 庆祝和弦 |

### 6.3 性能预算

- 每帧 JS 执行时间 < 8ms（60fps 下）
- 同时活跃粒子数 ≤ 60
- 音效并发数 ≤ 3（避免 cacophony）
- 动画元素 GPU 内存占用 < 100MB

---

## 7. 总结

本方案将游戏行业的 juiciness 理论系统映射到 Memory Anki 的复习场景中，通过 **即时反馈、状态强化、节奏感、过度反馈** 四大原则，在不干扰学习效率的前提下提升操作愉悦感。所有效果均通过 `cue()` facade 统一调度，自动适配 `prefers-reduced-motion`，并提供了完整的效果强度分级表与具体参数，可直接用于开发实现。
