## 随心模式 · 多汁化思维导图 Game Feel 原型

产出：`HTML-preview/juicy-mindmap-runtime.html`（单文件，2777 行，130 KB，无外部依赖）

### 架构决策
- **反馈运行时独立成层**：对齐 `docs/architecture/fx-director.md` 的 cue/recipe 思路。
  17 个 cue 配方集中在 `CUES` 表，UI 规格面板直接读同一张表，所以面板显示的就是真实参数，不是另写一份文案。
- **六段式时间轴**统一为：悬停/预备 → 敲击瞬间 → 判定定格 → 爆发扩散 → 惯性吸收 → 结果结算。
  小/中/大事件只是同一套语言的不同裁剪，不另起分支。
- **业务层与视觉层强制分离**：`Biz` 是唯一真值源；粒子、冲击波、飘字、镜头抖动全部是临时层。
  评分时 `+EXP` 飘字随 JUICE 强度缩放（视觉），结算面板「真实经验」由业务规则算（业务），刻意不相等。
- 声音用 WebAudio 纯合成，无外部资源。

### 过程中修掉的真实缺陷（不是样式问题）
1. **单击 250ms 延迟**：原本用 setTimeout 区分单/双击，导致每次点击都有延迟。
   手感第一条底线是零延迟 → 改为单击立即响应 + 独立 `dblclick` 事件。
2. **业务状态被 DOM 绑架**：`onCardClick` 开头 `if(!el) return` 会让元素缺失时业务不推进。
   改为状态机不依赖 DOM，视觉走可选旁路。
3. **收卡把状态变更放在 setTimeout 里**（最严重）：后台标签页被节流时卡片已不可见，
   但树仍认为它们展开。改为业务状态立即生效，动画用 ghost 副本独立播放。
4. `markAnswered` 非幂等（重复计数）；冲击波 DOM 泄漏（只 push 不 remove）。

### 验证方式
用 Node 把内联脚本剥出、`eval` 到 DOM 桩上跑状态机断言，覆盖：
两步左键、后代遮挡、右键收卡不翻回自身、叶子右键空操作、收卡后重新发出、徽章子树计数、评分不污染。
18 条断言全绿（其中 2 条最初的失败暴露了上面第 3 个缺陷）。
