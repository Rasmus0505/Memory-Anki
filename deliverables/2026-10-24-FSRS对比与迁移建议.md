# FSRS 与固定阶梯：真实数据对比（2026-10-24）

> 这份报告只回答一个问题：**把宫殿复习从固定阶梯换成 FSRS，会怎样影响真实排期和每日负担？**
> 结论来自本机数据库的只读回放，不修改任何学习数据。
>
> 后续进展：FSRS 适配器和实时影子记录已经落地，生产排期没有改变。实时对比与严格回放见
> `2026-10-24-FSRS影子适配基线.md`。本文是迁移前的趋势对比；这里的“有效评分操作 1,535 条”
> 按全库统计，影子基线只回放当前活跃单元（1,345 条），两者口径不同。

## 1. 数据与口径

| 项目 | 数值 |
| --- | ---: |
| 活跃复习单元 | 299 |
| 有评分历史 | 242 |
| 无评分历史（新单元） | 57 |
| 有效评分操作 | 1,535 |
| 评分分布 | 忘记 6 / 困难 387 / 记得 1,037 / 轻松 105 |
| 当前阶段分布 | 0:65，1:21，2:72，3:17，4:54，5:50，6:18，7:2 |

- 数据库：本机同步数据目录中的 `memory_palace.db`，以只读方式打开。
- 时间口径：数据库存 UTC-naive，按北京时间解释；学习日仍按凌晨 3 点翻页。
- 回放只取未撤销、未被替换的评分操作；每条评分按当时的 `before_state_json` 还原起点。
- FSRS 参数：`desired_retention=0.9`、最大间隔 365 天、学习步长 10 分钟 / 1 小时；对比固定阶梯时使用生产同款确定性 fuzz。
- 保留的生产规则：提前复习不推进、同一天第二次“困难”不重复降级、通过至少排到次日。
- **没有**模拟当天重试、手动改期、以及考试结束后的重新排期；这是一份趋势对比，不是对记忆效果的预测。

## 2. 下一次点“记得”之后的到期日

| 相对固定阶梯 | 单元数 | 占比 |
| --- | ---: | ---: |
| 提前 >30 天 | 4 | 1.3% |
| 提前 8–30 天 | 11 | 3.7% |
| 提前 1–7 天 | 26 | 8.7% |
| 同一天 | 67 | 22.4% |
| 延后 1–7 天 | 56 | 18.7% |
| 延后 8–30 天 | 60 | 20.1% |
| 延后 >30 天 | 75 | 25.1% |

**191 / 299 个单元会被排得更晚，只有 41 个更早。** 这符合 FSRS 的行为：它按每个单元自己的稳定性算间隔，而不是所有单元共用一张阶梯表；你历史上记得牢的单元会被拉长，反复“困难”的单元会被缩短。

回放校验：阶段与当前库一致 247/299（82.6%），到期日一致 165/299（55.2%）。到期日差异主要来自历史上的手动调整、旧规则和回放没有覆盖的“当天再次出现”规则，所以“切换后怎么排”以库中当前阶段/到期日为准，而不是只信回放。

> 后续修正：影子基线补上了当时的重试次数，并按规则生效日期过滤。2026-10-22 起的 162 条真实评分已经可以 **0 条不一致**地回放；上面的全历史一致率只作趋势参考。

## 4. 叠加考试冲刺模式后的真实窗口

当前考试设置为 **2026-12-20，冲刺模式开启**，所以长间隔会被拉回考前一天（2026-12-19）之前的最后 7 天。上面的 90 天口径会高估 FSRS 的收益，必须单独看：

| 指标（2026-10-24 至 2026-12-19） | 固定阶梯 | FSRS |
| --- | ---: | ---: |
| 总复习次数 | 1,200 | 815（−32%） |
| 有复习的天数 | 56 | 55 |
| 单日峰值 | 131（今天） | 112（今天） |
| 有复习日的平均 | 21.43 | 14.82 |
| 最后 7 天总量 | 336 | 223（−34%） |
| 最后 7 天峰值 | 60 | 37 |
| 被拉回最后 7 天的次数 | 203 | 242 |

关键结论：**即使把考试边界算进去，FSRS 仍然把总负担降低约三成，并把考前最后一周的峰值从 60 降到 37。** 但 FSRS 会有更多长间隔被拉回最后一周（242 次对 203 次），所以迁移时必须专门测试 `SprintHorizon` 的交互，不能只测无考试场景。

## 5. 目标保持率的选择

FSRS 的 `desired_retention` 直接决定负担。以同一批历史状态重放：

| 目标保持率 | 90 天总量（无考试边界） | 有考试边界总量 | 最后 7 天总量 |
| ---: | ---: | ---: | ---: |
| 0.85 | 509 | — | — |
| 0.90 | 661 | 815 | 223 |
| 0.95 | 1,021 | 1,042 | 232 |

- **0.90** 是推荐起点：总量比阶梯低约三成，最后一周峰值明显下降。
- **0.95** 更稳，但 57 天窗口内总量只比阶梯低约 13%，且几乎每天都有复习；如果考前焦虑明显、想要更高把握，可以切到 0.95。
- 不建议 0.85：虽然最省，但冲刺阶段的目标是“记住”，不是“减少卡片”。

## 6. 建议的迁移方式

不要直接改默认算法。按风险从低到高：

1. **先补规则测试**：把 `MIN_PASSED_STAGE`、提前复习锁定、困难同日只降一次、忘记归零、确定性 fuzz 五条产品规则，用当前阶梯写成回归测试。即使最后不迁移，这组测试也应当保留。
2. **写适配器**：保持 `rate_unit(...)` 签名不变，内部委托 FSRS；复用现有 `fsrs_runtime.py`，不要新建第二套 FSRS 集成。
3. **加字段与批量回放**：给 `review_unit_states` 加 FSRS 状态列，按 `review_unit_rating_operations` 的真实历史逐单元回放；写入可撤销的调度批次记录。
4. **并排运行**：同一批单元同时算阶梯和 FSRS 的到期日，先给“差异清单”，不直接改库。
5. **小范围切换**：按学科或宫殿分批切换，观察一周真实负担与评分分布，再决定全量。
6. **保留回退**：阶梯至少保留一个版本周期；迁移批次可撤销。

## 7. 还缺哪些验证

- 真实“忘记/困难”后的 FSRS 表现：当前回放里忘记只有 6 次，样本很少。
- 考试结束后的排期：本报告只算到考前一天，没有模拟考后恢复。
- 同日重试与提前复习：当前口径排除了这两类，生产里它们会改变次日负担。
- 前端“下次复习”预览：切换前必须保证按钮承诺的日期与后端实际写入一致。
- 真实使用一周的负担：数字是模拟，最终要看你在新排期下每天实际点多少张。

## 8. 一句话结论

FSRS 值得做，但应当**先适配、再并排、再分批切换**；推荐目标保持率从 0.90 开始，保留 fuzz，并把考试冲刺边界作为一等回归场景。按当前真实数据，57 天窗口内总复习量约从 1,200 降到 815，考前最后一周峰值约从 60 降到 37。
